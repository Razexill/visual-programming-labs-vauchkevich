Настройка Redis в n8n

Данный документ описывает процесс развертывания базы данных Redis, настройки подключения к ней из платформы n8n и реализации базовых операций (создание, чтение, удаление).

## 1. Запуск Redis в Docker

Для работы с Redis использовался Docker. Контейнер был запущен в фоновом режиме с пробросом стандартного порта 6379.

Использованная команда:

```bash
docker run -d --name redis -p 6379:6379 redis:7
```

**Параметры:**

- `-d` — запуск в фоновом режиме (detached).
- `--name redis` — имя контейнера.
- `-p 6379:6379` — проброс порта (хост:контейнер).
- `redis:7` — используемый образ (7-я версия).



## **2. Создание Credentials в n8n**

Так как n8n и Redis работают в разных контейнерах (или n8n в Docker, а Redis на хосте), для связи необходимо использовать специальный сетевой адрес.

В n8n был создан новый Credential типа **Redis** со следующими настройками:

- **Host**: `host.docker.internal`
- **Port**: `6379`
- **Password**: *(оставлено пустым, так как Redis запущен без пароля)*
- **Database Number**: `0`

> **Важно:** Использование `host.docker.internal` позволяет контейнеру n8n обращаться к портам хост-машины (твоего компьютера), где и запущен Redis.



## **3. Реализация Workflow (Создание и чтение)**

Для проверки записи и чтения данных был собран workflow `flow-09-redis`.  
**Цепочка нод:** `Manual Trigger` → `Redis (Set)` → `Redis (Get)`.

**Нода Redis (Set):**

- **Operation**: `Set`
- **Key**: `vauchkevich`
- **Value**: `hello_lab4`

**Нода Redis (Get):**

- **Operation**: `Get`
- **Key**: `vauchkevich`

**Результат:** После выполнения нода `Get` успешно вернула значение `hello_lab4`, что подтверждает корректную работу записи и чтения.

## **4. Реализация Workflow (Удаление и проверка)**

Для проверки удаления данных был собран workflow `flow-10-redis`.  
**Цепочка нод:** `Manual Trigger` → `Redis (Delete)` → `Redis (Get)`.

**Нода Redis (Delete):**

- **Operation**: `Delete`
- **Key**: `vauchkevich`

**Нода Redis (Get)** — используется для проверки:

- **Operation**: `Get`
- **Key**: `vauchkevich`

**Результат:** После удаления нода `Get` вернула `null` (пустое значение). Это подтверждает, что ключ `vauchkevich` был успешно удален из базы данных.

> **Примечание:** В текущей версии n8n встроенная операция `Exists` (проверка наличия) отсутствует в базовой ноде Redis, поэтому проверка осуществлялась через операцию `Get` (если ключа нет, возвращается `null`).



## **5. Проблемы и их решение**

В ходе работы возникла проблема, когда нода `Get` возвращала `null` сразу после записи. Причиной было то, что при тестировании запускались отдельные шаги (Execute step), а не весь workflow целиком. После запуска всего workflow (Execute Workflow) данные начали корректно записываться и читаться.

Также важно следить за тем, чтобы обе ноды (`Set` и `Get`) использовали один и тот же **Credential** и одинаковый **Database Number** (в нашем случае `0`).
